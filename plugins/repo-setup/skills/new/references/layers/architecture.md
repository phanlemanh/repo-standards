# Layer: architecture

**Framing.** How is the application structured inside the repo?

**Depends on:** context. Say how those decisions constrain this layer.

**Only one sensible answer when:** it is a small single-purpose tool or library. Then say it in one line and move on.

**Stack `claude-plugin`:** not applicable. Archetypes structure an application; a plugin marketplace is one folder per plugin under `plugins/`. Say that in one line, record `status: not_applicable` with it as `why`, and move on.

## Options

Offer two or three. Put anything the user already named on the list, even if you would not
recommend it. Say when each option would be wrong.

| Option | Why | Trade-off | Wrong when | Label |
|---|---|---|---|---|
| No archetype | Nothing to maintain | Boundaries are not enforced | Several business domains are expected | `automated` |
| `modular-monolith` | One deployment with enforced module boundaries | Boundaries need upkeep | A single small purpose | `automated` |
| `service-api` | Contract-first API with breaking-change checks | More layers; needs `ts-api` or `fastapi` | Nothing else consumes the system | `automated` |
| Event-driven, several services, full-stack web | May fit a larger system | Not generated by this plugin | One team and one deployment suffice | `manual` |

Labels: `automated` (`apply.py` does it and it is verified), `partial` (the core is automated and
the manual steps are listed), `manual` (only recorded, with guidance; `doctor` does not score it).

**Recommendation when the user hands this to Claude:** no archetype for a small tool, `modular-monolith` for a product with several domains, `service-api` when others call it.

## Recording

Write the result to `layers.architecture` in `setup-blueprint.yaml`: `status`, `source` (`user` or
`proposed`), `automation`, `choice`, `why`, `rejected`, `manual_steps`. A layer marked `manual` is
not applied at all, so when a layer mixes both, use `partial`: keep what `apply.py` can do in `choice`
and put the rest in `manual_steps`.
Choice keys: `archetype`.
