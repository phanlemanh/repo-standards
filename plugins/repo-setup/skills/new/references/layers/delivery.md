# Layer: delivery

**Framing.** Where does this run and how does it get there?

**Depends on:** architecture, stack. Say how those decisions constrain this layer.

**Only one sensible answer when:** it is a library or CLI with nothing to deploy. Then say it in one line and move on.

**Stack `claude-plugin`:** not applicable. Nothing is deployed: a plugin is delivered by its marketplace and a tagged release (level `team` adds a workflow that publishes a GitHub Release for each version tag). Say that in one line, record `status: not_applicable` with it as `why`, and move on.

## Options

Offer two or three. Put anything the user already named on the list, even if you would not
recommend it. Say when each option would be wrong.

| Option | Why | Trade-off | Wrong when | Label |
|---|---|---|---|---|
| Nothing yet | Nothing to run | Deploy work comes later | It runs for other people now | `automated` |
| `container` | Works on any container platform | Images and a registry to manage | Nothing runs on a server | `automated` |
| Serverless or a platform of your choice | Fits an existing platform | Not generated by this plugin | A container would do | `manual` |

Labels: `automated` (`apply.py` does it and it is verified), `partial` (the core is automated and
the manual steps are listed), `manual` (only recorded, with guidance; `doctor` does not score it).

**Recommendation when the user hands this to Claude:** nothing yet for a tool; `container` when it runs on a server.

## Recording

Write the result to `layers.delivery` in `setup-blueprint.yaml`: `status`, `source` (`user` or
`proposed`), `automation`, `choice`, `why`, `rejected`, `manual_steps`. A layer marked `manual` is
not applied at all, so when a layer mixes both, use `partial`: keep what `apply.py` can do in `choice`
and put the rest in `manual_steps`.
Choice keys: `deploy` (`container` or leave unset).
