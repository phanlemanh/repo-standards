# Layer: domain

**Framing.** What are the main business concepts, who may do what, and which data is personal?

**Depends on:** architecture, ai. Say how those decisions constrain this layer.

**Only one sensible answer when:** the project has no real domain yet: say it can be added later with `/ontology-add`. Then say it in one line and move on.

**Stack `claude-plugin`:** not applicable. A plugin marketplace has no business domain to model, so `ontology/` and `wiki/` are not generated; its glossary and decision records stay in its own docs. Say that in one line, record `status: not_applicable` with it as `why`, and move on.

## Options

Offer two or three. Put anything the user already named on the list, even if you would not
recommend it. Say when each option would be wrong.

| Option | Why | Trade-off | Wrong when | Label |
|---|---|---|---|---|
| Seed 3-5 concepts now | Shared names from day one | A few more questions | The domain is still unclear | `automated` |
| Start empty, add later | Fastest | Names may drift | Several people start at once | `automated` |
| Choose a database now | Decides early | Not generated by this plugin | No persistent data yet | `manual` |

Labels: `automated` (`apply.py` does it and it is verified), `partial` (the core is automated and
the manual steps are listed), `manual` (only recorded, with guidance; `doctor` does not score it).

**Recommendation when the user hands this to Claude:** start empty. With the agent tier the sample ontology is used until the user describes the domain.

## Recording

Write the result to `layers.domain` in `setup-blueprint.yaml`: `status`, `source` (`user` or
`proposed`), `automation`, `choice`, `why`, `rejected`, `manual_steps`. A layer marked `manual` is
not applied at all, so when a layer mixes both, use `partial`: keep what `apply.py` can do in `choice`
and put the rest in `manual_steps`.
Choice keys: `seed` (list of concepts), `database`; seeded concepts are written with `.claude/skills/ontology-add/SKILL.md` after apply.
